# Icon Machine i18n — 設計文件

**狀態:** 已通過 brainstorm,待寫實作計畫
**日期:** 2026-05-10
**範圍:** 為 production UI(`index.html` + `main.js`)導入 zh-Hant / en 雙語切換。架構支援未來擴充更多語言。`regression.html` 與 canvas 渲染層完全不動。

---

## 1. 目標 & 非目標

### 目標
- production UI 的所有使用者可見字串走 i18n 線(zh-Hant + en 雙語並列)。
- 切換機制:dropdown(header)+ localStorage 記憶 + URL `?lang=` override + 首次依 `navigator.language` 偵測。
- 切語言以 dynamic DOM update 完成,**不**reload、**不**重置 seed input、**不**重畫 batch grid。
- 架構可擴充:加新語言只需新增 `i18n/<lang>.js` + 在 `i18n.js` 的 `SUPPORTED` array push 一個值。
- 維持「零 build step、純 vanilla JS、純 `<script src>`」原則。
- 維持「同 seed 同輸出」契約 — i18n 只動 DOM 文字,不影響任何 canvas 內容。

### 非目標(明確 defer)
- regression.html 的 i18n(內部視覺迴歸工具,只 zh-Hant)
- palette family 名稱(steel / fire / frost / ...)— 只出現在 regression spec dump,不在 production UI
- spec dump 內容(regression specs.json)的翻譯
- 數字 / 日期 locale 格式化(本 app 沒此需求)
- RTL 語言支援(目前語言皆 LTR)
- 動態 lazy-load 翻譯檔(vanilla 無 build,~30 keys × 2 lang 體積可忽略,直接全載)
- Translation interpolation `t('foo', {name})`(目前所有字串靜態)
- Pluralization rules(目前無複數變化字串)
- ja / ko / zh-Hans 等其他語言(架構就緒,實際填表是後續工作)

### 設計姿態
i18n 是純 UI 層工具,不改 canvas 渲染、不改 seed 流程、不改既有檔案責任邊界。新增 i18n runtime + 翻譯檔,改 `index.html` 的 element 加 `data-i18n-*` 屬性,`main.js` 加啟動 + dropdown event 接線。

## 2. 整體架構

```
新增:
  i18n/zh-Hant.js   ← window.I18N_ZH_HANT = { 'app.title': '...', ... }
  i18n/en.js        ← window.I18N_EN      = { 'app.title': '...', ... }
  i18n.js           ← window.I18N runtime: init / t / applyI18n / setLang / getLang
  scripts/check-i18n.mjs  ← Node static checker:diff lang tables + grep HTML keys

修改:
  index.html        ← 加 <script src> 三個、加 lang dropdown、user-facing element 加 data-i18n-key / data-i18n-attr-<x>
  main.js           ← 啟動加 I18N.init(),綁 dropdown change event

不動:
  regression.html、potion.js / sword.js / spear.js / palette.js / pixel-utils.js / random.js
  snapshots/、scripts/snapshot-regression.mjs、所有 baseline PNG
```

### 載入順序(index.html `<script>` 排列)
```
random.js
palette.js
pixel-utils.js
potion.js
sword.js
spear.js
i18n/zh-Hant.js     ← 新增
i18n/en.js          ← 新增
i18n.js             ← 新增,在 main.js 之前
main.js
```

i18n 必須在 `main.js` 之前,因為 `main.js` 啟動會 call `I18N.init()`。
翻譯檔(`i18n/zh-Hant.js`, `i18n/en.js`)必須在 `i18n.js` 之前,因為 `i18n.js` 載入時會讀取 `window.I18N_ZH_HANT` 跟 `window.I18N_EN`。

## 3. i18n.js — Runtime API

```js
window.I18N = (function () {
  const SUPPORTED = ['zh-Hant', 'en'];
  const DEFAULT_LANG = 'zh-Hant';
  const STORAGE_KEY = 'iconmachine.lang';

  const TABLES = {
    'zh-Hant': window.I18N_ZH_HANT,
    'en':      window.I18N_EN,
  };

  let currentLang = DEFAULT_LANG;

  function resolveInitialLang() { /* 見 §3.1 */ }
  function validateTables()      { /* 見 §3.2 */ }
  function t(key)                { /* 見 §3.3 */ }
  function applyI18n(root)       { /* 見 §3.4 */ }
  function setLang(lang)         { /* 見 §3.5 */ }
  function init()                { /* resolveInitialLang → validateTables → applyI18n */ }

  return { init, t, applyI18n, setLang, getLang: () => currentLang, SUPPORTED };
})();
```

### 3.1 `resolveInitialLang()` — Lang resolution chain
依序檢查,第一個命中為準:

1. **URL `?lang=<value>`** — 解析 `location.search`,若值在 `SUPPORTED` 中:採用,並寫入 localStorage(讓分享連結持久化)。若值不在 `SUPPORTED`(例 `?lang=fr`):跳過,**不**寫 localStorage(避免 invalid 值持久化)。
2. **localStorage `iconmachine.lang`** — 若存在且在 `SUPPORTED` 中:採用。否則跳過。
3. **`navigator.language`** — 取小寫 prefix:
   - 開頭 `zh` → `zh-Hant`(MVP 不分繁簡,zh-CN/zh-TW/zh-HK 都對到 zh-Hant)
   - 開頭 `en` → `en`
   - 其他 → 跳過
4. **Fallback** — `DEFAULT_LANG`(`zh-Hant`)

讀 localStorage 用 try/catch(私密瀏覽模式可能 throw)。

### 3.2 `validateTables()` — Dev-time integrity check
比對 `I18N_ZH_HANT` 跟 `I18N_EN` 的 key set。任一邊缺 key 就 `console.error`:
```
[i18n] table mismatch:
  Missing in en:      [foo.bar, baz.qux]
  Missing in zh-Hant: []
```
**不 throw** — 應用照跑(用 fallback 機制)。這個 check 是給開發者的 console 早警,不是 production 用戶體驗的閘門。

### 3.3 `t(key)` — Lookup
```js
function t(key) {
  const table = TABLES[currentLang];
  if (table && key in table) return table[key];
  // fallback 1: zh-Hant
  if (currentLang !== 'zh-Hant' && 'zh-Hant' in TABLES && key in TABLES['zh-Hant']) {
    return TABLES['zh-Hant'][key];
  }
  // fallback 2: key 本身 + warn
  console.warn(`[i18n] missing key: ${key} (lang=${currentLang})`);
  return key;
}
```

三段 fallback:current lang → zh-Hant → key string。最壞情況使用者看到的是 key 而不是空白,確保 UI 不會破。

### 3.4 `applyI18n(root = document)` — DOM update
逐項處理:

1. **`<html lang>`** — 設成 `currentLang`(影響 screen reader 與 CSS `:lang()` 選擇器)。
2. **`[data-i18n-key]`** — `root.querySelectorAll('[data-i18n-key]')`,對每個 element 設 `el.textContent = t(el.dataset.i18nKey)`。`<title>` 也有 `data-i18n-key`,會自然被這條 selector 命中(`document.querySelectorAll` 包含 `<head>` 內 element),不需要特殊處理。
3. **`[data-i18n-attr-<name>]`** — MVP 用 hardcoded selector array `['placeholder', 'title', 'aria-label']` 跑,各自 `root.querySelectorAll('[data-i18n-attr-X]')` → `el.setAttribute(X, t(value))`。MVP 實際只用到 `placeholder` 跟 `title`,`aria-label` 留 hook。

> **dataset 命名:** HTML `data-i18n-attr-aria-label` → JS `el.dataset.i18nAttrAriaLabel`(連字符段轉 camelCase,標準 dataset 行為)。但因為 MVP 只跑 `placeholder` / `title` / `aria-label`,直接 hardcode 對應關係,不靠通用轉換邏輯。

> **為什麼用 `data-i18n-attr-<name>` 而不是 `data-i18n-attr="placeholder:key,title:key2"`:** 前者一個 element 多個屬性各自一個 attribute、selector 直接 `[data-i18n-attr-placeholder]`,parse 邏輯零;後者要 split string 容易出錯。

### 3.5 `setLang(lang)`
```js
function setLang(lang) {
  if (!SUPPORTED.includes(lang)) return;     // 防呆
  if (lang === currentLang) return;          // no-op
  currentLang = lang;
  try { localStorage.setItem(STORAGE_KEY, lang); } catch (_) {}
  applyI18n();
}
```

不 reload。也不會 dispatch event 給其他系統 — i18n 是純 UI,不影響 canvas。

### 3.6 `init()`
```js
function init() {
  currentLang = resolveInitialLang();
  validateTables();
  applyI18n();
}
```

由 `main.js` 在啟動時 call。

## 7. main.js 接線

```js
// === 啟動 ===
I18N.init();  // 在最頂端、所有 getElementById 之後、generate() 之前

const langSelect = document.getElementById('lang-select');
langSelect.value = I18N.getLang();
langSelect.addEventListener('change', (e) => {
  I18N.setLang(e.target.value);
  // 不需要 re-generate 也不需要 re-renderBatchGrid:
  // - canvas 內容不依賴 lang
  // - seed 不變
  // - dropdown option text 已被 applyI18n() 同步更新
});

// 既有 init 序維持不變
seedInput.value = generateRandomSeed();
generate();
renderBatchGrid();
```

`I18N.init()` 不碰 input value,跟 `generateRandomSeed()` 順序無依賴。但要在所有 DOM 取址完成後 — 既有 `getElementById` 都在檔頂,沒問題。

## 8. scripts/check-i18n.mjs — Static checker

Node script,可手動 / pre-commit / CI 跑。**不**綁定 npm script(MVP),user 可手動 `node scripts/check-i18n.mjs`。

### 邏輯
1. 讀 `i18n/zh-Hant.js` 跟 `i18n/en.js`,用 `vm` 模組 sandbox eval、抓 `I18N_ZH_HANT` / `I18N_EN`(因為這兩個檔走 `window.X = {...}` 形式,要 fake `window`)。
2. 比對兩個 table 的 key set,輸出兩邊各自缺什麼。
3. 讀 `index.html`,regex 抓所有 `data-i18n-key="..."` 跟 `data-i18n-attr-<name>="..."` 的 value。
4. 比對:
   - HTML 用了但翻譯表沒有 → `Used in HTML but missing in tables: [...]`
   - 翻譯表有但 HTML 沒用 → `Defined but unused: [...]`(警告級,不 fail)
5. exit 1 if 有 missing(fail);exit 0 if 只有 unused(warn)或全乾淨。

### Output 範例
```
Checking i18n consistency...
  ✓ zh-Hant: 23 keys
  ✓ en:      23 keys
  ✓ Tables match
  ✓ HTML keys: 22 used (app.title via <title>, others via data attrs)
  ⚠ Unused in HTML: lang.label
PASS
```

## 9. 驗證流程

### 9.1 Static
- `node scripts/check-i18n.mjs` → 期望 PASS。

### 9.2 Manual smoke test(user 自己開 `index.html`)
1. 預設(無 localStorage、無 URL param、navigator zh / en / 其他):
   - zh-* → 看到 zh-Hant
   - en-* → 看到 en
   - 其他 → 看到 zh-Hant(fallback)
2. `index.html?lang=en` → en,reload 後仍 en(localStorage 寫入)
3. dropdown 切 en → 即時換成 en、seed input 不變、batch grid 不重畫、preview 不重畫
4. dropdown 切回 zh-Hant → 即時換回中文
5. `?lang=fr`(invalid)→ 走完 chain 退到 zh-Hant 或 navigator-detected,localStorage 不被污染
6. console 應乾淨(無 missing key warning,無 table mismatch error)

### 9.3 Snapshot regression
- `npm run snapshot` 必須仍能跑、結果 byte-identical(因為 regression.html 沒動,且 i18n 不影響 canvas)。
- 跑一次 `npm run snapshot` 確認沒打到 baseline。

## 10. 風險清單(impl 後須驗證)

| # | 風險 | 預期視覺/行為 | 驗證方式 |
|---|---|---|---|
| 1 | `<select>` option 改 textContent 後 dropdown 不 reflow | 切 lang 後關閉 dropdown 再開,選項應顯示新 lang 文字 | 手動切 lang → 開 type-select |
| 2 | `<title>` 改 textContent 是否生效 | 切 lang 後分頁標題立即更新 | 手動切 lang → 看分頁標題 |
| 3 | `localStorage` 在 file:// 協定下行為 | 寫入 / 讀取應正常(file:// origin 有獨立 localStorage) | 手動切 lang → reload → 設定持續 |
| 4 | URL `?lang=` invalid 不污染 localStorage | 開 `?lang=fr`,localStorage 不應出現 `iconmachine.lang=fr` | DevTools Application → localStorage |
| 5 | i18n.js 是 main.js 啟動硬依賴 | 註解掉 `<script src="i18n.js">` 後 main.js 會在 `I18N.init()` throw ReferenceError → batch grid 不會 render。這是預期行為(硬依賴),HTML 內 zh-Hant 文字仍可見因為 i18n.js 沒 overwrite。**Acceptable**,不做防呆。 | 手動實驗確認失敗模式 |
| 6 | navigator.language 為 `zh-CN` 時對到 `zh-Hant` | 預期(MVP 不分繁簡):匹配 prefix `zh` → 用 zh-Hant | 手動 override navigator.language |
| 7 | iframe / 隱私模式 localStorage throw | try/catch 應吞掉 error、currentLang 仍能用、UI 不破 | Safari 私密視窗測試 |
| 8 | type select 第 1 個 option 是 zh-Hant 「任意 (any)」,改 lang 後變 「Any」,但 select.value 仍是 `'any'` | value 不變,只 textContent 變 | DevTools 查 select.value |
| 9 | applyI18n() 在 `validateTables()` 報 mismatch 時仍跑 | 報 error 後 UI 仍能顯示(用 fallback)|看 console + UI |
| 10 | dropdown 切 lang 後,如果使用者再點 reroll,不會帶舊 lang 副作用 | reroll 跟 lang 完全解耦 | 手動 reroll 測 |

## 11. 開放議題 / 已決定但記錄

- ✅ **不 i18n regression.html** — 內部工具,user 自己一個人看
- ✅ **不 i18n family 名稱**(steel/fire 等)— 不在 production UI
- ✅ **MVP 兩語** — 架構支援更多,加 ja/ko/zh-Hans 是純資料工作
- ✅ **Dropdown native lang name 不走 i18n** — 母語識別 UX 慣例
- ✅ **dropdown + localStorage + URL ?lang= override** — 三者並存,priority 為 URL > localStorage > navigator > default
- ✅ **Dynamic update 不 reload** — 避免重置 seed / batch grid
- ✅ **單檔 vs 分檔:選分檔** — `i18n/zh-Hant.js` + `i18n/en.js`,雖然 PR review 友善度差不多,但符合 user 偏好
- ✅ **不在 t() 做 interpolation** — YAGNI
- ✅ **HTML 保留 zh-Hant 作為 fallback / source-of-truth** — i18n.js 沒載入時 UI 仍能讀
